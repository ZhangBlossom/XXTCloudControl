# 王者荣耀清理验证记录（2026-09-26）

目标应用：`com.levelinfinite.sgameGlobal`。当前仍为实机验证阶段，设备 profile 保持 `manual_test=true`、`verified=false`；尚未启用自动清理后复用。

## 已完成

- 实机盘点应用容器约 10.6 GiB，主要资源位于 `Library/Application Support/com.levelinfinite.sgameGlobal/QtsVFSCache`（约 10.2 GiB）。
- 新增 `tests/honor_cleanup_trial.lua`：关闭远控和游戏、写入零额度，备份非资源数据至手机 `Library/XXTCloudCleanupRecovery` 下的私有目录，将资源暂存到应用容器外，执行 XXTouch `clear.app_data`，恢复资源并重新写入零额度。
- 本次实机返回 `awaiting_login_verification`，表示清理 API 成功且资源恢复完成，不表示账号隔离验收通过。
- 清理后重启游戏，出现通知/跟踪提示和条款、出生日期确认页。尚未直接进入旧账号。关闭提示后已看到 Guest 和其他登录方式入口；尚未点击任何登录方式，仍需验证游客凭据是否残留。
- 调度器收尾要求 `closed` 报告同时满足 `stopped=true` 和 `remaining=0`。清理等待独立为 120 秒，未确认完成则隔离设备。

- 第二次关闭/启动仍出现首次条款和出生日期提示，未自动进入原账号大厅。证据：`evidence/honor-clean-second-launch-20260926.png`。用户尚需自行处理此提示，才能继续验证不同登录入口。
- Lua 异常路径模拟通过：清理 API 返回失败/抛异常仍恢复资源；资源恢复失败不报告成功；游戏关闭失败或容器异常不执行清理；重复运行不覆盖原报告。此测试不证明凭据隔离。

## 尚未完成的验收

1. 用户完成首次启动提示后，确认登录页无旧账号自动恢复；再次关闭/启动仍如此。
2. 检查保留资源是否无需重新下载，并确认残留的钥匙串、共享目录、第三方登录状态不会带出旧账号。
3. 实测不同登录方式和再次登录后的重复清理。首次启动页本身不足以证明凭据已完全清除。
4. 将已验证范围封装为生产 cleanup/verify 模块后，接入六分钟会话结束链路，再验证下一笔订单安全复用。

## 当前边界

- 未清空系统钥匙串、其他应用或 Apple ID。
- 手机本地保留一份私有恢复备份用于本次实验；生产流程不能长期累积上一个用户的凭据备份。
- 原始资源目录按路径保留，是否包含用户状态仍待验收，不能仅凭目录名认定全部内容都是公共资源。
- 实验脚本失败时需人工检查报告中的恢复目录，不自动重新分配，不盲目重跑。
- 调度器修改已完成针对性竞态测试，但尚未重启正在运行的服务器加载本轮修改。
