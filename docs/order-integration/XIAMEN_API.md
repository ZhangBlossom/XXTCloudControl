# 云手机接入接口文档 v1

## 1. 接口说明

厦门确认用户订单可以履行后，调用本接口提交订单信息。成功时返回可直接打开的云手机远控页面，用户在已打开的目标 App 中登录自己的账号并限时操作。厦门无需另外查询准备状态或获取连接地址；可先调用第 8 节的设备查询接口，为用户显示可用数量和预计等待提示。

- 方法：`POST`
- 路径：`/orders/v1/connect`
- 协议：HTTPS
- 请求类型：`Content-Type: application/json`
- 响应类型：`application/json`

服务域名和支持的游戏清单由双方联调时提供。本文示例域名 `https://cloud.example.test` 不是实际服务地址。本版无需传入对接密钥或计算请求签名。

## 2. 请求参数

普通请求示例：

```json
{
  "order_id": "xm-20260922-001",
  "bundle_id": "com.example.game",
  "product_name": "游戏商品",
  "price": 1.98,
  "currency": "CNY",
  "country_code": "CN",
  "quantity": 5,
  "retry": false
}
```

| 参数 | 类型 | 必填 | 说明                                                                                                                                                                    |
|---|---|---|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| order_id | string | 是 | 厦门订单号，1～128 字节，不含斜杠、反斜杠和 NUL；建议使用字母、数字、连字符                                                                                                                            |
| bundle_id | string | 是 | 游戏 iOS Bundle ID，最长 255 字节，仅英文字母、数字、点、连字符，须使用双方约定的游戏标识                                                                                                                |
| product_name | string | 是 | 商品名字，不能省略、为空或全为空白字符，最长 200 字节                                                                                                                                                   |
| price | number | 是 | 游戏内商品原始价格，例如 648、1.98；范围 0.01～1000000，最多两位小数. 例如648钻石礼包,游戏内部售价为648元,则传递648即可                                                                                          |
| currency | string | 否 | 省略或空字符串默认 CNY；使用三位大写货币代码，例如 CNY、USD。本期仅记录，不参与购买拦截                                                                                                                                               |
| country_code | string | 否 | 订单所属国家或地区，使用 ISO 3166-1 两位大写字母代码，例如 CN（中国）、US（美国）、JP（日本）；省略或空字符串默认 CN。该字段仅记录订单地区，不替代 currency，也不修改手机或游戏账号的地区设置 |
| quantity | integer | 是 | 本次允许放行的购买请求次数，范围 1～100                                                                                                                                                |
| retry | boolean | 否 | 默认 false；true 表示厦门主动申请一次新的手机使用会话，详见第 6 节                                                                                                                              |

本期按价格数值完全相等和剩余次数限制购买，不按商品名字、币种或地区拦截；同价格的其他商品也可被放行。

648、648.0、648.00 视为相同价格。省略 currency 与显式传 CNY 视为相同参数。省略或传空字符串 country_code 与显式传 CN 视为相同参数；country_code 属于订单参数，普通请求重复调用时须保持一致。未知字段、非法字段类型、多个 JSON 值或超过 64 KiB 的请求体将被拒绝。

## 3. 成功响应

HTTP 状态码为 200，响应示例：

```json
{
  "code": 200,
  "message": "成功",
  "order_id": "xm-20260922-001",
  "viewer_url": "https://cloud.example.test/order-viewer#order=example-session&token=example-access-token",
  "expires_at": "2026-09-22T09:05:02Z"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | integer | 200 表示成功，与 HTTP 状态码一致 |
| message | string | 成功时为“成功” |
| order_id | string | 厦门本次提交的订单号 |
| viewer_url | string | 完整远控页面地址，直接交给对应用户打开，无需拼接或解析内部参数 |
| expires_at | string | 本次会话截止时间，RFC 3339 UTC；展示时可转换为本地时区 |

所有字段在顶层，没有 data 外层包装。viewer_url 是完整的 HTTPS 网页地址，不是 WebSocket 地址。厦门无需实现手机画面或操作协议。

接入步骤：

1. 后端确认用户订单后，调用本接口；从请求发起到收到结果，前端显示“等待分配设备中”。
2. 收到 code=200 后，将 viewer_url 和 expires_at 返回给该订单对应用户的前端
3. 前端立即跳转到 viewer_url，或显示“进入云手机”链接让用户点击打开新标签。
4. 远控页面自动建立连接并展示手机画面；目标 App 已打开，用户登录自己的账号后开始操作。无需扫码或再次申请设备。

前端收到厦门自己后端转交的成功结果后，直接跳转：

```javascript
if (result.code === 200) {
  window.location.assign(result.viewer_url);
} else {
  // 展示 result.message，由厦门业务决定如何处理。
}
```

如需新标签打开，可在成功后显示链接，由用户点击，避免异步请求完成后自动弹窗被浏览器拦截：

```javascript
// enterLink 为页面上的“进入云手机” <a> 元素。
if (result.code === 200) {
  enterLink.href = result.viewer_url;
  enterLink.target = "_blank";
  enterLink.rel = "noopener noreferrer";
  enterLink.hidden = false;
}
```

必须原样使用完整地址，包括 `#` 后面的部分；不要拆解、删除或重新拼接参数，也不要对整个 URL 再做一次编码。此地址用于浏览器导航，不是用 fetch 请求来获取手机画面的数据接口。若厦门使用中转跳转页，须确认中转过程完整保留该地址。当前不支持 iframe 内嵌。

## 4. 失败响应

失败时不返回 viewer_url。例如请求参数不合法：

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json
```

```json
{
  "code": 400,
  "message": "订单参数不合法，请检查必填字段、金额、币种、数量和请求格式",
  "error_code": "invalid_order"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | integer | 失败状态码，与 HTTP 状态码一致 |
| message | string | 可读的失败原因，可用于展示 |
| error_code | string | 错误类型标识，用于程序判断；不要通过匹配 message 文案控制业务 |

## 5. 响应状态码与错误说明

| HTTP / code | error_code | message 示例 | 说明 |
|---|---|---|---|
| 200 | 不返回 | 成功 | 使用 viewer_url 进入手机页面 |
| 400 | invalid_order | 订单参数不合法，请检查必填字段、金额、币种、数量和请求格式 | 修正参数；retry=true 也不能跳过参数校验 |
| 409 | order_conflict | 订单号已存在，但订单参数与原订单不一致 | 普通请求不能修改原参数；主动重试可提交新的有效订单参数 |
| 409 | not_active | 订单会话已结束、到期或正在回收，无法连接 | 普通请求不能重开已结束会话；如需新的使用机会，由厦门决定发送 retry=true |
| 409 | request_in_progress | 该订单有请求正在处理，请勿并发提交 | 同订单有请求正在处理会话变更，避免并发发送新请求 |
| 503 | previous_session_unavailable | 原会话暂时无法结束，本次未分配新手机，请联系平台处理 | 主动重试无法结束旧会话，暂不交付新会话；旧入口可能已失效 |
| 503 | device_unavailable | 手机准备或连接交付失败，请联系平台排查 | 无可交付入口，由厦门决定后续操作 |
| 503 | storage_unavailable | 平台订单存储或配置暂不可用，请稍后使用原订单重试 | 暂时无法处理，由厦门决定是否再次请求 |
| 504 | prepare_timeout | 手机准备超时，请使用相同订单信息重试 | 设备准备或远控入口交付未完成；不是暂无空闲设备的等待超时 |
| 500 | internal_error | 平台服务异常，请稍后使用原订单重试 | 未预期异常，联系平台排查 |

message 是给人阅读的原因；同一 code 可能有多种 error_code。任何非 200 响应均不得作为成功交付。是否重新申请使用机会始终由厦门决定，不因某个状态码自动增加次数或时长。

## 6. 普通请求与主动重试

### 6.1 普通请求：retry=false 或不传

- 订单首次申请：正常分配一次手机使用会话。
- 订单已有当前有效会话且参数相同：返回当前入口，不重复分配、不增加次数、不延长截止时间。
- 订单已使用完、到期或正在结束：返回 not_active，不重新分配。
- 与当前会话的订单参数不一致：返回 order_conflict。
- 如果该订单此前有主动重试，普通请求以最近一次会话为准，不返回更早的入口。

### 6.2 主动重试：retry=true

当厦门决定允许用户再次使用手机时，使用原 order_id 并显式传 true：

```json
{
  "order_id": "xm-20260922-001",
  "bundle_id": "com.example.game",
  "product_name": "游戏商品",
  "price": 1.98,
  "country_code": "CN",
  "quantity": 5,
  "retry": true
}
```

- 不因该订单已经使用过而拒绝，按本次请求重新申请一个手机使用会话。
- 本次价格和数量以本次请求为准；次数重新按 quantity 计算，使用时长重新为 6 分钟，不承接旧会话的剩余次数或剩余时间。
- 原会话尚未结束时，先结束原会话，再交付新的会话；不同时向同一订单开放两台手机。旧入口会失效。
- 新会话不保证是另一台物理手机，返回的新入口为准。
- 参数校验和手机正常可交付等条件仍需满足，retry=true 不代表一定成功；暂时没有空闲手机时等待分配。
- 每次 retry=true 都表示新的业务申请，**不是获取原链接，也不是同一次申请的幂等补发**。没有 retry_id 字段；成功后再次传 true 会再次申请。
- 没有历史会话时，retry=true 也可正常申请首次会话。
- 如果旧会话已结束但新手机分配失败，旧会话不会恢复。

是否允许重新使用、何时重试及重试次数由厦门自行判断。普通的网络重发和重新申请使用机会必须区分。

## 7. 等待分配与页面使用说明

### 等待分配

- 有可用设备：分配并准备手机，准备完成后返回 viewer_url。
- 暂无可用设备：请求保持等待，待设备可分配并准备完成后返回 viewer_url，不因暂时无设备立即报错。
- 请求尚未返回时，厦门前端显示 **“等待分配设备中”**。可结合第 8 节的查询结果提示“预计约 X 秒后有设备可用”；预计时间未知时只显示等待文案。
- 收到成功响应后停止等待提示，打开远控页面；收到失败响应后停止等待提示，显示 message。
- 等待时间不计入手机的 6 分钟使用时长；使用时间从手机准备完成开始，以 expires_at 为准。
- 查询设备数量不会预留设备，也不能替代申请接口。提交申请后不要仅因长时间未响应而并发重复申请或自动发送 retry=true。

### 网络异常

- 只有请求仍在进行时显示“等待分配设备中”。客户端超时、连接断开或收到错误后，应结束本次等待提示并告知用户，不能一直显示处理中。
- 网络中断不代表原申请未生效；如需继续获取原申请结果，可由厦门选择用相同 order_id 和参数、retry=false 再次调用，平台应关联原申请，不新增使用机会。
- 如决定重新申请一次，则传 retry=true；不要让网络层无条件自动补发带 true 的请求。
- 网关故障可能返回非 JSON，按网络异常处理，不能当作成功。

### 页面与业务口径

- 用户打开 viewer_url 后自动连接，在已打开的目标 App 中登录自己的账号；无需扫码、绑定设备或额外配置。
- 使用时间从手机准备完成开始，以 expires_at 为准；迟到打开页面会减少可用时间。
- 页面支持直接跳转或新标签打开，目前不支持 iframe 嵌入。
- 用户可提前结束使用，到期也会自动结束；调用方不用调用额外释放接口。
- 链接只交付给对应用户，不分发给多个用户，也不记录到分析埋点。请完整使用链接，不假定其内部参数格式。
- 次数在购买请求被放行时消耗，用户取消或购买后续失败不自动返还次数。
- 接口成功仅表示云手机可交付，不代表游戏商品已到账；是否到账或发货由业务方核对。

## 8. 查询可用设备

用于厦门在申请前或等待期间展示设备情况，不分配、不预留手机。统计范围为支持指定游戏的设备。

- 方法：`GET`
- 路径：`/orders/v1/availability`
- 查询参数：`bundle_id` 必填，与申请接口的游戏标识一致；`currency` 可选，默认 CNY，使用三位大写代码；本期不按币种筛选设备。

请求示例：

```http
GET /orders/v1/availability?bundle_id=com.example.game&currency=CNY
```

暂无空闲设备、预计约 120 秒后有设备可用：

```json
{
  "code": 200,
  "message": "成功",
  "available_count": 0,
  "next_available_at": "2026-09-23T03:02:00Z",
  "estimated_wait_seconds": 120
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | integer | 查询成功为 200，与 HTTP 状态码一致 |
| message | string | 查询成功为“成功” |
| available_count | integer | 当前符合要求、可立即分配的空闲设备数量；不包含离线、异常、准备中或清理中的设备 |
| next_available_at | string / null | 预计最早有设备可用的时间，RFC 3339 UTC；已有空闲设备时为查询时的当前时间，无法估算时为 null |
| estimated_wait_seconds | integer / null | 距预计最早有设备可用还需多少秒；已有空闲设备为 0，无法估算为 null |

- 有空闲设备时，例如 available_count=2、estimated_wait_seconds=0；真正申请时仍可能被其他请求先分配。
- 没有空闲设备时，根据当前使用会话的截止时间估算最早释放时间；实际可用时间还受清理、提前结束和设备异常影响，不保证到点即可交付。
- 该时间表示设备预计可用时间，不是当前用户排队等待时长的承诺；已有其他等待申请时，当前用户可能需要等待更久。
- 没有符合条件的设备，或设备均离线、异常、处于无法估算的准备或清理状态时，返回 available_count=0，两个时间字段为 null；不承诺 6 分钟内必有设备。
- 无可用设备仍是查询成功，返回 code=200。参数非法返回 400 / invalid_order，服务异常返回 500 / internal_error 或 503 / storage_unavailable，失败响应格式同第 4 节。

本文中的域名、订单号和响应数据仅用于示例。
