# Last War 真实订单联调

日期：2026-09-24。本地服务、真实 USB 连接的 iPhone 12 Pro Max、实际安装的 `com.lastwar.ios`。没有以模拟设备或单元测试替代接口请求。

**结论：真实申请、手机配额下发、启动命令、独立订单远控页面的视频和触摸、到期失效及停止游戏已验证。手机已有商品登录浮层持续遮挡，未看到 Last War 主界面，因此整体交付验收未通过。没有执行真实购买或账号清理。**

## 实际请求与响应

`POST http://127.0.0.1:46980/orders/v1/connect`，Content-Type: application/json。本机联调模式无需对接请求密钥，只接受真正来自回环地址的申请，不信任 X-Forwarded-For。

```json
{
  "order_id": "xm-lastwar-20260924-001",
  "bundle_id": "com.lastwar.ios",
  "product_name": "648元商品联调",
  "price": 648,
  "currency": "CNY",
  "quantity": 5,
  "retry": true
}
```

最新一次真实请求约 1.25 秒返回 HTTP 200：

```json
{
  "code": 200,
  "expires_at": "2026-09-24T07:34:10.08621Z",
  "message": "成功",
  "order_id": "xm-lastwar-20260924-001",
  "viewer_url": "http://127.0.0.1:46980/order-viewer#order=<真实会话ID>&token=<已省略，测试入口已到期>"
}
```

成功响应后打开真实返回的 viewer_url，看到实际手机视频；点击手机输入框后，手机键盘弹出，证明订单页面的触控通道有效。没有使用管理员远控页面来冒充订单链接验证。

## 本次修正

1. Go 转发手机 HTTP 请求时，空 query 必须发送 {}。此前 nil 编码为 null，而手机 Lua 对其 next(query)，实际准备失败。新增协议回归断言。
2. 原脚本对 app.quit 后立即检查进程已退出的假设不成立。实测 app.close 后 Last War 从 pid=1543 变为 0，改用关闭后有界等待确认。准备、收尾及异常路径使用同一处理。
3. 订单页面 fingerId=0 与原版触控编号范围不一致，改用原版使用的 28；修复后实际点击弹出键盘。
4. Lua 原先把所有失败抹成 session_failed，现保留内部错误文本，以便从手机报告定位原因。

参考：[XXTouch app.quit](https://xxtouch.app/docs/handbook/app/app.quit/)、[app.close](https://xxtouch.app/docs/handbook/app/app.close/)。

## 人工联调模式

清理模块尚未具备，因此新增明确的本机联调开关 XXTCC_LOCAL_ORDER_TEST=1，以及设备档案 manual_test=true、verified=false。此模式只允许一个人工测试设备档案，公开入口源站必须为 127.0.0.1；只放宽本次同一操作者的清理前置条件，不声称设备完成生产验收。订单、脚本、手机、视频和触摸均为真实链路。

结束后脚本停止游戏、配额置零并报告 manual_cleanup_required；即使收到 closed，服务也不自动释放人工测试设备。测试中的三次人工重新准备均停止服务、保留原日志备份、记录原因后进行。分别是上传前失败、确认进程退出且配额为零后的准备失败、同一操作者到期后的触控复测。它们不是已实现的自动账号清理，也不能作为生产恢复流程。最终会话仍保持隔离。

手机原始配额文件在首次改写前已备份为 com.iapguard.runtime.plist.before-lastwar-20260924；没有自动恢复可购买配额，结束后保持 enabled=true、648=0。
